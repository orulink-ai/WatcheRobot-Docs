# 固件版本管理

WatcheRobot 将“切换固件版本”“清除用户数据”和“设备救援”视为三件不同的事。这样可以避免用户为了降级误删数据，也避免所谓恢复出厂只清掉一部分配置。

## 客户端切换版本

正常升级或降级应通过客户端切换版本。可选择的版本、稳定等级和硬件兼容范围，以客户端实际展示的发布清单为准。

执行前应确认：

- 设备保持稳定供电；
- 当前硬件型号受目标版本支持；
- 目标固件和资源格式相互兼容；
- 降级是否要求同时清除不兼容的持久化数据。

如果客户端没有显示目标版本，不建议绕过校验直接写入 OTA 分区。

## 清除设备数据

“清除设备数据”用于转让设备、退出账号或解决持久化配置问题。它应删除 Wi-Fi、配对关系、账号凭据、下载的 Application 和用户配置，但不负责选择历史固件。

清除前应先备份仍需保留的内容。操作完成后，设备需要重新配网和配对。

## OTA 自动回滚

OTA 自动回滚用于处理“新固件能写入，但启动后无法通过健康检查”的情况。Bootloader 应返回上一个已确认可用的 OTA 槽，而不是依赖用户进入设置页操作。

自动回滚是设备可靠性机制，不等于用户主动降级。只有新版本启动验证失败时才应触发。

## 有线救援

当应用无法启动、两个 OTA 槽都不可用，或客户端无法建立正常设备连接时，使用 USB 和官方 Daemon 维护能力执行有线救援。

有线救援应使用官方发布包，校验硬件型号、分区表和镜像摘要。除非明确需要整机擦除，否则不要自行添加 `erase-flash`。

## 能力边界

| 用户目标         | 正确入口            |
| ---------------- | ------------------- |
| 正常升级或降级   | 客户端版本管理      |
| 删除个人数据     | 清除设备数据        |
| 新 OTA 启动失败  | Bootloader 自动回滚 |
| 设备无法正常启动 | USB 有线救援        |
