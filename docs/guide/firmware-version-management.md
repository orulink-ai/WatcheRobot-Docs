# 固件版本管理

WatcheRobot 将“切换固件版本”“重置设备数据”“启动失败回滚”和“设备救援”视为四件不同的事。这样可以避免用户为了降级误删数据，也避免把清除设置误解为恢复某个历史固件。

## 客户端切换版本

正常升级或降级应通过客户端切换版本。可选择的版本、稳定等级和硬件兼容范围，以客户端实际展示的发布清单为准。

执行前应确认：

- 设备保持稳定供电；
- 当前硬件型号受目标版本支持；
- 目标固件和资源格式相互兼容；
- 降级是否要求同时清除不兼容的持久化数据。

如果客户端没有显示目标版本，不建议绕过校验直接写入 OTA 分区。

## 嵌入式 Factory Reset（当前实现）

::: warning Factory Reset 不是固件降级
设备设置中的 **Factory Reset** 只重置当前固件管理的数据，不会回退固件版本，也不会刷入一个内置的“出厂版本”。重启后仍运行重置前的当前固件版本。
:::

这个入口当前已经生效。用户在设备的 **Settings > Factory Reset** 页面滑动确认后，嵌入式会执行以下操作：

| 当前动作 | 实际效果 |
| --- | --- |
| 断开 Wi-Fi 并清除 Wi-Fi 凭据 | 设备重启后需要重新配网 |
| 调用 `nvs_flash_erase()` | 擦除默认 NVS 分区中保存的设置和凭据 |
| 删除 `/spiffs/app_center` | 清除下载到该目录的 Application 包 |
| 重启设备 | 使用当前 OTA 应用分区重新启动 |

当前路径不会主动擦除 SD 卡，也不会擦除默认 NVS 和 `/spiffs/app_center` 之外的存储区域。因此，不能把它理解为“整片 Flash 清空”。转让设备前，如果产品版本还会把用户数据写入其他分区或 SD 卡，应按对应功能单独检查和删除。

建议保留嵌入式入口，因为设备离线、Wi-Fi 配置损坏或需要转让时，用户仍需一个不依赖客户端的重新配网入口。产品文案可逐步统一为“重置设备数据（Factory Reset）”；正常升级或降级仍由客户端版本管理负责。

## OTA 自动回滚

OTA 自动回滚用于处理“新固件能写入，但启动后无法通过健康检查”的情况。Bootloader 应返回上一个已确认可用的 OTA 槽，而不是依赖用户进入设置页操作。

自动回滚是设备可靠性机制，不等于用户主动降级。只有新版本启动验证失败时才应触发。

## 有线救援

当应用无法启动、两个 OTA 槽都不可用，或客户端无法建立正常设备连接时，使用 USB 和官方 Daemon 维护能力执行有线救援。

有线救援应使用官方发布包，校验硬件型号、分区表和镜像摘要。除非明确需要整机擦除，否则不要自行添加 `erase-flash`。

## 能力边界

| 用户目标 | 正确入口 | 固件版本结果 |
| --- | --- | --- |
| 正常升级或降级 | 客户端版本管理 | 切换到用户选择且兼容的版本 |
| 清除设置并重新配网 | 设备设置中的 Factory Reset | 保持当前固件版本 |
| 新 OTA 启动失败 | Bootloader 自动回滚 | 返回上一个已确认可用的 OTA 槽 |
| 设备无法正常启动 | USB 有线救援 | 写入所选官方救援包 |
